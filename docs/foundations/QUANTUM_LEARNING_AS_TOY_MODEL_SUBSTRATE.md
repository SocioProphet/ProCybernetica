# Quantum Learning as Toy-Model Substrate

**Status:** Draft v0.1
**Track:** Foundation / research-method doctrine
**Purpose:** Clarify how SocioProphet uses quantum learning in the same disciplined sense that mechanistic-interpretability research uses toy models: as a controlled substrate for isolating structural mechanisms before operational adoption.

---

## 1. Thesis

SocioProphet uses quantum learning as a controlled toy-model substrate for governance dynamics.

The claim is methodological, not promotional. Quantum learning is used to isolate dependency, observability, cancellation, reachability, feedback, and partition behavior under clean structural conditions.

It is analogous to how interpretability research uses small toy models to study superposition: the toy model is not the deployed frontier model, but it exposes mechanisms that would otherwise be too entangled to understand directly.

---

## 2. What this permits

Quantum learning can be used to study:

- dependency propagation;
- control reachability;
- observability partitions;
- cancellation/interference;
- adaptive feedback loops;
- capability-tier invocation boundaries;
- monitor-network robustness;
- falsification triggers for feedback and dependency concentration.

---

## 3. What this does not claim

This doctrine does not claim:

- that deployed SocioProphet governance requires quantum hardware;
- that agent systems are literally quantum circuits;
- that the quantum substrate replaces base architecture schemas;
- that quantum toy models validate production safety by themselves;
- that capability-tier invocation is automatic.

Quantum learning is a research substrate. Production governance still requires schemas, fixtures, validators, evidence receipts, safety cases, and falsification observables.

---

## 4. Relationship to the quantum dependency substrate

The quantum dependency substrate capability tier remains opt-in.

Quantum learning provides experimental models that can inform the six capability-tier schemas:

- `dependency_control_graph.v1.json`
- `control_reachability_record.v1.json`
- `observability_partition.v1.json`
- `shared_dependency_ancestry.v1.json`
- `dependency_cancellation_record.v1.json`
- `adaptive_feedback_loop.v1.json`

It should not force those schemas into the base architecture.

---

## 5. Relationship to falsification

Quantum-learning toy models are useful only if they generate falsifiable claims.

A useful toy model should state:

- which governance mechanism it isolates;
- which dependency variables it controls;
- which observables it measures;
- which production claim it informs;
- which falsification observable it connects to;
- which non-claims prevent overextension.

---

## 6. Non-claims

A quantum-learning toy model is not production evidence unless promoted through the evidence fabric.

A quantum-learning result may support doctrine, schema design, or falsification hypotheses, but it cannot by itself promote a runtime control, safety case, or capability tier.
